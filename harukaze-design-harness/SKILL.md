# Harukaze式 デザインハーネス構築スキル

## 0. このスキルの目的

AIにデザインを頼むと「それっぽい画面」はすぐ出る。しかし事業として使えるかは別の話。  
このスキルは「なぜその構成か」「ブランドとつながっているか」「成果にどうつながるか」という**判断軸**を、フォルダとファイルに落とし込む仕組みを作る。

**デザインハーネスの4層:**
1. **制約する** — ブランドカラー・フォント・禁止パターン
2. **コンテキストを渡す** — 設計原則・ユーザー像・感情ゴール
3. **検証する** — 成果物が目的を達成しているかのチェックリスト
4. **フィードバックする** — 失敗と改善をルールに戻すループ

---

## 1. スキル起動時の動作

### スキル起動直後の必須確認

1. プロジェクトパスを確認（作業ディレクトリ or ユーザーに確認）
2. `{project}/.claude/design-harness/DESIGN.md` が既に存在するか確認
   - **存在する場合**: 「既存のデザインハーネスが見つかりました。更新しますか？新規作成しますか？」と確認
   - **存在しない場合**: Phase 1 の質問へ進む

---

## 2. 質問フロー（4フェーズ）

### 🔴 質問の進め方

- **1フェーズごとにまとめて質問し、回答を受けてから次フェーズへ**（往復を最小化）
- 各フェーズの冒頭で「Phase N: ○○を聞きます」と宣言してから質問を並べる
- 回答が「なし」「わからない」「後で」の場合はスキップしてデフォルト値を使う
- 全フェーズ完了後、ファイル生成に進む前に「このまま生成します。よろしければEnterを押してください」と確認する

---

### Phase 1: 事業理解（必須・スキップ不可）

以下を1回のメッセージで全部聞く:

```
【Phase 1: 事業の基本情報】以下の4問に答えてください。

Q1. 事業の種類・ジャンルは何ですか？
    （例: オンラインスクール / コーチング / EC / SaaS / メディア / リアル店舗 など）

Q2. ターゲット顧客を教えてください。
    （属性・年代・状況・抱えている悩みを具体的に）

Q3. デザインで達成したいことは何ですか？（複数OK）
    （例: 集客LP改善 / ブランド統一 / CV率向上 / 信頼感の醸成 / SNS映え など）

Q4. 主に使う媒体はどれですか？（複数OK）
    （LP / SNS投稿 / セミナースライド / LINE / バナー広告 / 全部）
```

---

### Phase 2: ブランド制約（スキップ可・デフォルト値あり）

```
【Phase 2: ブランドルール】以下5問に答えてください。「わからない」はスキップOKです。

Q5. ブランドカラーを教えてください。
    （具体的な色名・HEXコード・または「温かみのある赤系」「信頼感のある青」等の雰囲気でもOK）

Q6. フォント・書体の方向性は？
    （モダン / 温かみ / 高級感 / ポップ / 専門的 / まだ決めていない）

Q7. コピー・文章のトーンは？
    （フレンドリー口語体 / 丁寧敬語 / 励ます応援系 / 専門的で格調高い / 強めのセールス）

Q8. 「絶対使ってはいけない」表現・デザインパターンはありますか？
    （例: 「稼げる」「簡単に」という言葉NG、過度な赤はNG、派手なアニメーション禁止 など。なければ「なし」）

Q9. 参考にしたいブランド・デザイン事例があれば教えてください。
    （競合他社でもOK。なければスキップ）
```

---

### Phase 3: コンテキスト収集（スキップ可）

```
【Phase 3: 設計コンテキスト】以下を教えてください。

Q10. 顧客に「このデザインを見てどう感じてほしいか」を教えてください。
     （例: 「この人に頼めば安心だ」「自分でもできそう」「憧れる」「信頼できる専門家だ」）

Q11. 既存のデザイン素材・参考画像があればファイルを共有してください。
     （なければスキップ）

Q12. 過去のデザインで「刺さった」「外した」経験があれば教えてください。
     （なければスキップ）
```

---

### Phase 4: 検証・フィードバック設計（スキップ可）

```
【Phase 4: 品質基準と改善ループ】最後の質問です。

Q13. 「良いデザインができた」と判断する基準は何ですか？
     （例: CV率が上がる / 顧客から「プロっぽい」と言われる / 統一感がある / クライアントがすぐOKを出す）

Q14. デザインを誰がレビューしますか？
     （自分のみ / 信頼できる誰か / チーム / クライアント）

Q15. 改善ループをどう回しますか？
     （案件ごとに振り返る / 月1で見直す / 気づいたとき / まだ考えていない）
```

## 3. ファイル生成ルール

全フェーズの回答を受けたら、以下のフォルダ構造を**一括生成**する。

### 生成先ディレクトリ

```
{project}/.claude/design-harness/
├── DESIGN.md
├── constraints/
│   ├── brand-rules.md
│   └── prohibited.md
├── context/
│   ├── user-personas.md
│   ├── use-cases.md
│   └── design-principles.md
├── verification/
│   └── quality-checklist.md
└── feedback/
    └── feedback-log.md
```

プロジェクトパスが不明な場合は作業ディレクトリ（`pwd`）直下の `.claude/design-harness/` を使う。

```markdown
> 更新時は `/harukaze-design-harness` スキルの「更新モード」を使うか、直接編集してください。

---

{Q6の回答を記載}

### コピー・文章トーン
{Q7の回答を記載}

{Q8の回答を箇条書きで記載。なしの場合は「現時点で制約なし」}

## 2. コンテキスト（Context）

### 設計原則
{回答全体から導出した3〜5条の設計原則を記載}

### ターゲット顧客像
{Q2の回答を基に構造化。属性・状況・悩み・ゴールを箇条書き}

### 感情ゴール（このデザインを見てどう感じてほしいか）
{Q10の回答をそのまま記載}

### 参考事例

## 3. 検証チェックリスト（Verification）

### ルールベース検証（客観的に確認できること）

- [ ] コピーのトーンがブランドルールと一致しているか

### 体験検証（主観・人間レビュー用）
- [ ] 感情ゴールを達成しているか: 「{Q10の感情ゴール}」と感じられるか
- [ ] ターゲット顧客が「自分ごと」として受け取れるか
- [ ] {Q13の判断基準}を満たしているか

### レビュー担当
{Q14の回答}
```

### constraints/brand-rules.md — 生成内容

Q5〜Q7の回答を詳細に展開。色・フォント・余白・コンポーネント使用ルールを記載。

### constraints/prohibited.md — 生成内容

Q8の回答を展開。「なぜ禁止か」の理由も添える（ブランドの文脈から推論）。

### context/user-personas.md — 生成内容

Q2の回答をペルソナ形式に展開:
- 基本属性（年代・職業・状況）
- 抱えている悩み・課題
- デザインに期待すること
- このブランドに感じてほしい印象

### context/use-cases.md — 生成内容

Q4の媒体 × Q3のゴールを組み合わせて利用シーン別に整理。

### context/design-principles.md — 生成内容

Q3・Q7・Q10から導出した設計原則を展開（DESIGN.mdの簡略版の詳細バージョン）。

### verification/quality-checklist.md — 生成内容

DESIGN.mdの検証チェックリストをより詳細に展開した作業用チェックシート。制作物ごとに使い回せる形式。

```markdown
## ルール昇格キュー（DESIGN.mdに追加予定）
（同じパターンが2回出たらここに書いて、次のハーネス更新時に反映する）
```

```
   - デザイン依頼時: harukaze-design-aiが自動でDESIGN.mdを読み込みます
   - ルール追加時: feedback-log.md → DESIGN.mdの順で更新してください
   - 6ヶ月後: /harukaze-design-harness を再起動して「更新モード」でブラッシュアップを
```

## 5. harukaze-design-ai との連携

`harukaze-design-ai` スキルのStep 1（スキル起動直後）で以下を追加確認:

> `{project}/.claude/design-harness/DESIGN.md` が存在する場合、制作前に必ずReadして制約・コンテキストとして取り込む。DESIGN.mdで定義されたブランドカラー・禁止パターン・感情ゴールはすべてのデザイン制作に適用する。

---

## 6. 更新モード

既存のDESIGN.mdがある場合、「更新モード」で起動:

1. 既存 DESIGN.md を Read して現状を把握
2. 「どこを更新したいですか？（制約 / コンテキスト / 検証 / フィードバック / 全体見直し）」と1問だけ聞く
3. 該当セクションだけ質問・更新する（全15問は聞かない）
4. 変更内容を `feedback/feedback-log.md` にも記録する
